# 003 — Transcript data source & ingestion pipeline

**Goal:** resolve what "Lenny's Podcast / Newsletter transcript repository" refers to, then build ingestion (load → normalize → chunk → embed → store).

## Finding the real data source

Searched the web for "Lenny's Podcast newsletter transcript repository GitHub dataset" instead of guessing a URL. Found `github.com/LennysNewsletter/lennys-newsletterpodcastdata` — an **official** repo under the `LennysNewsletter` GitHub org, explicitly described as a "free starter pack ... in AI-friendly markdown," with a companion `index.json` and per-episode YAML-frontmatter markdown files.

**Checked the license before using it** (`LICENSE.md` in that repo, fetched directly):
> "You may use the starter dataset in this public repo for personal, non-commercial work ... including publishing projects built with it ... You may not redistribute the raw starter dataset files."

A take-home submission is personal, non-commercial work, and "publishing a project built with it" is explicitly permitted — but committing the raw `.md` files into this repo's public GitHub would be "redistributing the raw dataset files," which is explicitly **not** permitted.

**Decision:** `scripts/fetch_lennys_transcripts.py` downloads transcripts from that repo into `data/transcripts/lennys_podcast/` at setup time; that directory is git-ignored. The repo itself only ever contains fetch *code*, never the fetched *content*. This satisfies both the assignment (real ingestion from the real source, fully traceable metadata) and the data owner's license.

**Fallback for offline/no-network evaluation:** wrote 5 short, entirely original, fictional podcast-style transcripts (`data/transcripts/sample_synthetic/`, fictional show "Growth Signals," fictional host/guests) covering activation, pricing, retention loops, positioning, and PMF signals — so the app has something to answer questions about even with zero network access and zero license considerations. Documented clearly as synthetic in `data/transcripts/README.md` and in each file's `source_url` (`example.com/...`).

## Ingestion pipeline

- `loader.py`: format-specific loaders for `.md` (the real dataset's YAML-frontmatter format), `.json` (synthetic samples / hand-authored), `.txt`, `.vtt`. Never invents metadata — a missing field is stored `null`.
- `normalizer.py`: collapses whitespace, strips inline timestamps, and converts the real dataset's `**Speaker Name** (00:12:34):` cue format into `Speaker Name:` (keeps attribution, drops token-wasting timestamps).
- `chunker.py`: paragraph-aware chunking targeting ~350 tokens with ~60-token overlap (tiktoken `cl100k_base` as a model-agnostic token proxy), falling back to sentence-splitting for oversized paragraphs.
- `pipeline.py`: dedupes on a SHA-256 content hash (`transcript_documents.content_hash`, unique constraint) so re-running ingestion is always safe; `--force` re-ingests.

**Verified:** unit tests for chunking (empty input, overlap, oversized-paragraph fallback), normalization (timestamp stripping, speaker-format conversion), content hashing (stable + change-sensitive), and end-to-end `run_ingestion()` against a temp directory with a fake embedding provider (idempotency test: running ingestion twice produces one document, not two).
